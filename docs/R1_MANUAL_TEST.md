# R1 Android15/17 SukiSU 手动验收

本文面向用户提供的 Android15 / Android17、SukiSU 设备。候选版本为 `A0.11.0-r1 / 386`，使用 `r1test` 构建，包名 `com.nezhahq.agent.r1test`，显示名“哪吒探针 R1测试”。这是可并存的测试包；本文是手测步骤，不表示下列真机验收已经完成。

## 测试安装与连接

- 安装提供的独立测试包，保留现有正式版。正式升级仍保持 `com.nezhahq.agent`，并需要原发行签名。
- 在最新版面板建立专用测试节点，使用独立 UUID。记录测试时的 Dashboard 版本、Android 版本和 SukiSU 版本。
- 填写测试连接，使用有效 TLS 配置；启用探针后确认面板上线、CPU/内存/电池/流量持续上报。
- 首先保持高权限、远程命令、远程文件和 NAT 开关关闭，确认默认授权状态。

## 普通模式与 SukiSU

先开启“允许面板远程执行命令”，保持高权限关闭，调用：

```json
{"cmd":"/system/bin/id","args":["-u"]}
```

普通模式应返回测试应用自身 UID。再停止探针，在手机本地开启高权限模式，保存并启动，通过 SukiSU 的正常授权界面允许该测试应用，重新执行同一请求，应返回 UID 0。Root/Shizuku 模式属于连接配置，运行中不可编辑；远程命令和文件开关则可在运行中单独刷新。

现有后端选择优先使用已运行的 Shizuku。单独验收 SukiSU 时，在设备本地停止 Shizuku，再在探针停止状态关闭并重新开启高权限模式，保存并启动。若先前拒绝了 Root，请在管理器处理授权后再次关闭/开启高权限；失败的启用期间不会反复请求 su。只有测试包需要新增 SukiSU 授权。

## Exec 参数、输出和超时

| 场景 | 请求或动作 | 期望 |
| --- | --- | --- |
| 参数边界 | cmd=`/system/bin/printf`，args=`["%s\|%s", "空 格", "分号;$(id)"]` | 每个参数保持原文，未请求的 shell 表达式不执行 |
| 独立输出与退出码 | cmd=`/system/bin/sh`，args=`["-c", "printf out; printf err >&2; exit 7"]` | stdout=`out`，stderr=`err`，exit_code=7；结构化响应仍可解析 |
| stdin EOF | cmd=`/system/bin/cat`，stdin=`中文` | 返回原文并结束，不一直等待输入 |
| 超时 | 显式 sh -c 执行 `printf before; sleep 30`，timeout_seconds=5 | 有限时间返回 timed_out，保留已收到的 before；面板指标继续刷新 |
| 两路截断 | 两路各输出超过指定 max_output_bytes | 分别标记截断，命令仍能结束，不因管道满挂住 |
| 能力撤回 | 长命令运行时在手机关闭远程命令开关 | 新 MCP 命令被取消，新请求明确拒绝；已有旧终端按兼容说明处理 |
| 停止高权限运行 | 长任务运行时停止探针，再关闭高权限模式、保存并启动 | 停止后对应高权限任务/资源结束；重新启动普通模式时不恢复旧命令 |

上述 JSON 是 `server.exec` 工具的命令部分；通过面板调用时另提供目标 `server_id`。新 Exec 与旧 Task4 的外层 successful 含义不同，不能仅用退出码判断两者的协议是否一致。

## 文件读取

开启远程文件管理，用专用测试目录准备空文件、中文文本、二进制文件、隐藏项、软链接和大目录。SukiSU 模式可使用 `/data/local/tmp/nezha-r1-test`；普通模式按测试应用的存储权限选目录。

| 场景 | 期望 |
| --- | --- |
| 空目录、隐藏项与中文/换行名称 | 名称完整，show_hidden 的过滤与 total 一致 |
| 超过 5000 项 | 返回条目不超过 5000，total 为完整过滤后计数，truncated=true |
| 分段读取 | offset/length 生效，size 等于本段原始字节数 |
| UTF-8 与 Base64 | 文本解码合法；Base64 解码后的字节与原文件段一致 |
| SHA-256 | 与本次返回的原始段一致；不当作整个文件摘要 |
| EOF 外偏移、空文件 | 返回实际空段，未伪造内容 |
| 目录、FIFO、设备文件与最终软链接读取 | 明确业务错误，不永久等待 |
| 目录软链接结尾为 `/` 或 `/.` | 仍按最终软链接拒绝，不因路径形状绕过 nofollow |
| 无权限目录 | 返回权限错误，不显示为空目录成功 |
| 长 link_target / 控制字符导致结果过大 | 明确预算错误，不伪报完整 total、size 或散列 |

文件授权关闭期间不能启动新 FsList/FsRead；撤回时取消活动的新 MCP 文件任务。旧文件管理会话、上传下载仍按原兼容规则验收。API23–25 的 FsList 是明确能力错误，该限制不适用于用户的 Android15/17。

## 生命周期与资源

- 保持两条长命令并发时检查指标连续上报，再发起文件读取，确认旧短任务 worker 没有全部被长命令配额占用。
- 连续切换网络、停止/启动探针、修改连接并重载；确认没有重复采样、旧任务结果写入新连接或自动重放结果未知命令。
- 回归旧终端、NAT、文件上传下载。上传拒绝或最终保存失败后需重建旧文件会话，延迟残包不能当作新操作。
- 候选版后台至少运行 24 小时；记录设备、时间段、连接中断、异常重连、PSS/fd/任务/子进程趋势。短时 JVM/模拟器用例不能代替该验收。

## GPU 与版本显示

- 在可读到 GPU 的 SukiSU 模式确认型号及使用率正常；无法获取样本时允许省略，不能把缺失当作真实 0%。
- 当前没有可靠的独立显存来源，`memory_total=0` 表示未知；不能把系统 RAM 当显存验收。
- APK/界面版本是 `A0.11.0-r1`。面板 Host.version 为 `2.1.0+android.A0.11.0-r1`，用于最新版面板的 MCP 入口校验，仅承诺 Task15–17。本轮 Task12–14、18–20 仍明确 unsupported。

若多次失败后持续 BUSY，先确认 SukiSU 的待决授权已处理、旧命令确实结束。未知原生退出必须继续保有资源票；必要时真正终止并重开测试 App 进程。仅停启探针服务不会重建进程级的未知维护槽。

## 结果反馈

建议先反馈三项：普通/Root 两次 `id -u` 结果、执行中关闭远程命令的回收结果、目录枚举和分段读取结果。每条反馈包含候选版本、设备/Android/SukiSU/Dashboard 版本、对应场景、请求或操作、实际结果、是否可重复。日志或截图中的连接密钥、认证信息和文件正文按需要隐藏。

应用内授权撤回、Shizuku 管理器撤权和 SukiSU 管理器修改授权是不同动作。已启动的 UID0 进程不会仅因管理器修改后续 su 授权而自动变回普通 UID；Root 手测以应用停止/远程能力关闭后的实际进程回收为准，同时确认管理器拒绝后新请求不能获得高权。

正式覆盖安装、UUID/连接/授权保留和递增 versionCode 的修复恢复，需要使用原发行签名单独验收；独立测试包不替代这些记录。
